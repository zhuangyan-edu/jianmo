# jianmo：AI 视频「拔刀」镜头的可交互 3D 复刻

这份文档是项目的交接说明：目标是什么、已经定了哪些路线、素材现状、下一步做什么。
新开的对话（包括换账号后的对话）先读完这一份再动手。

## 1. 目标

把一段 4.9 秒的 AI 生成视频复刻成浏览器里的实时 3D 场景：

- **原片内容**：短发、白衬衫、深色裙的少女在废墟平台上半蹲拔刀，刀口爆出蓝白色电光和水花；背景是废墟和斜射的暖色逆光，前景有大颗虚化光斑，景深很浅。
- **必须做到**：能自由拖动视角观看，不是只能从原片机位看。
- **要加的原创内容**：拔刀之后来一段很帅的爆发（见第 5 节）。
- **验收标准**：氛围和镜头接近原片即可，**不要求逐像素一致**。
- **不做**：原片上的 "XIAOWANG Production" 水印不复刻。

原片视频没有放进仓库（仓库是公开的）。新对话需要对照原片时，请用户重新上传那段录屏。

## 2. 已定的路线

| 决定 | 结论 | 原因 |
|---|---|---|
| 技术栈 | 单页 HTML + Three.js，实时渲染 | 要能自由转视角 |
| 主角来源 | **用户用 Tripo 生成的模型**，不再走纯代码建模 | 纯代码做的脸到不了原片的精细度；用户只看最终画面 |
| 贴图 | 用去光版 | 视角和灯光都会变，电光要实时打在角色身上 |
| 骨骼 | 用自动绑定的 Mixamo 骨架（带手指） | 蹲姿和握刀需要可靠的蒙皮权重 |
| 头发、裙摆 | 不绑骨骼，用物理或顶点 shader 让它们飘 | 原片里两者都在动 |
| 特效、光斑、烟尘、体积光 | 全部用代码做 | 都是动态或虚化的东西，代码更可控 |
| 远景 | 2:1 全景天空图做环境光和背景（用户生成，在 `assets/sky-panorama.jpg`） | 提供环境光和反光 |
| 模型分工 | 画面相关的全部由主线程做；接口明确的模块（闪电、粒子、布料）可交给子代理；另用一个全新上下文的代理只看原片帧和截图来挑差距 | 风格统一最重要，拆太散会不协调 |

早期做过一个纯代码生成的动漫头模（`face/index.html`，约 20 万面，浏览器里现场生成）。
它证明了逆光、皮肤透光、眼睛发光这套 shader 可行，但脸和头发不够好，**现在只作为 shader 参考，主角不用它**。

## 4. 素材现状

全部由 Tripo 生成，都在 `upload-3d-models` 分支。高面数的那些都是单个网格、单个材质。

| 文件 | 内容 | 三角面 | 骨骼 | 判断 |
|---|---|---|---|---|
| `anime schoolgirl 3d model.glb` | 全身，T 字姿势 | 1.9 万 | Mixamo 53 根，含手指 | **身体用它**。头部粗糙（贴图糊、头发破面），要换头 |
| `anime girl head 3d model.glb` | 带黑色乱短发的头 | 185 万 | 无 | **换头首选**。发型和原片最像，但头发和头是一体的，头是歪的 |
| `bald female head 3d model.glb` | 光头，脸精细 | 193 万 | 无 | 备选，配下面的假发。眼睛偏淡、瞳孔不清，头是歪的 |
| `hair wig 3d model.glb` | 单独的头发壳，无贴图 | 181 万 | 无 | 备选，配光头。颜色要用 shader 给 |
| `anime girl 3d model.glb` | 全身，**坐姿**，细节最好 | 189 万 | 无 | 坐姿、裙子和腿粘连，没法绑骨做动画。只当造型和配色的参照 |
| `katana sword 3d model.glb` | 刀和刀鞘 | 193 万 | 无 | 质量好。刀和鞘在同一个网格里，要拆开 |
| `ancient ruin platform 3d model.glb` | 废墟平台 | 186 万 | 无 | 质量好，当主角脚下的地面 |
| `tripo_convert_451eb99b….glb` | 另一个角色（猫耳长发），无贴图 | 4.9 万 | 无 | 和本项目无关，疑似误传 |
| `tripo_convert_7f5380ad….zip` | 全身模型的 FBX 版和贴图 | — | — | 和 GLB 重复 |

预览图在 `docs/previews/`：`schoolgirl-rigged.jpg`、`schoolgirl-rigged-head.jpg`、`girl-head.jpg`、
`bald-head.jpg`、`hair-wig.jpg`、`girl-sitting.jpg`、`katana.jpg`、`ruin-platform.jpg`。

**全景天空图**：`assets/sky-panorama.jpg`，1774×887，日出云海加废墟。

- 左右接缝基本连续，只有一条很淡的竖线，接入时在接缝处做一小段混合即可。
- 分辨率偏低（原计划 4K）。背景本来就在景深虚化里，够用；有更高清的版本再替换。
- 画面中央有太阳，主逆光的方向要对准它。
- 色调比原片更蓝、更通透，原片是偏暖的烟尘感，靠雾和调色往回拉。
- 视点在云层之上，下半张是俯瞰的云海。平台会像悬在高空，和原片的地面废墟不同，用户看过效果后再决定是否保留。

## 5. 实施路径

**进度**：第 1、2 步已完成，第 3 步做了一半（角色已拼好，最终的光照和 shader 还没上）。

- 减面后的模型在 `assets/`：`body.glb`、`bald.glb`、`wig.glb`、`head.glb`、`katana.glb`、`ruin.glb`，合计约 17 MB。用 `@gltf-transform/cli` 的 weld、simplify、resize、webp 处理。
- 角色页面是 `character/index.html`：运行时切掉绑骨身体上权重属于 `Head` 骨骼的三角面，再把新头挂到 `Head` 骨骼上。
- **换头最终用的是 `bald` + `wig`，不是 `head`**。`head` 的发丝粘在脸上，贴图里还烘进了深色污痕，清不干净；光头的脸是干净的，假发又是独立网格。`?head=head` 可以切回去对比。
- 头的朝向是算出来的：按贴图颜色找到两只眼睛的顶点，取眼睛连线和眼周皮肤的平均法线，得到头的坐标系（`tools/analyse-head.js`），结果写在页面的 `SCANS` 里。
- 预览：`docs/previews/character.jpg`，两种头的对比在 `docs/previews/head-compare.jpg`。
- 脖子接缝：扫描头自带的脖子相对头是歪的，会从领口戳出来，所以只保留下巴以下一小段（`NECK_KEEP`），其余用身体自己的脖子；身体脖子和领口内侧贴图上的深色污痕在加载时重绘成肤色。
- **头发改用代码生成**（`character/hair.js`，默认开启；`?hair=wig` 切回假发模型）。在光头的头皮三角面上采样发根，用一个近似头骨的椭球做碰撞，头皮上另盖一层深色底。结构是对照用户生成的两个头发模型（假发、带头发的头）一条条学来的：
  - 发束是宽而扁的发片，到发梢分成一到三个尖；
  - 按真实发型裁剪：头顶长，鬓角和后颈短（`cutLong`/`cutShort`），长的上层盖在短的下层上；
  - 头皮分成若干"分区"（`sectionSize`），同一区的发束共用流向、S 形弯曲和发梢外翘的方式，区与区之间不同；
  - 整体轮廓是圆的：耳朵以下的发束往脖子方向收（`tuck`、`bell`），只有约三成分区的发梢向外翘；各分区长度差得比较开，下缘参差不齐；
  - 发束数量刻意压少、加宽（`clumps` 125、`sectionSize` 0.95），太多太细会显得杂乱；
  - 背风一侧的分区整体被风吹开；另有少量不属于任何分区的自由发丝（`flyaways`、`surface`）；
  - 材质在片元着色器里做了顺发丝方向的条纹和 Kajiya-Kay 高光；发梢摆动在顶点着色器里。
  - 预览 `docs/previews/hair-code.jpg`：最上一排是参照的模型，下面两排是代码生成的结果。
- 还没处理：眼睛瞳孔太淡；耳朵上方露出一块头皮；假发还不会动；用户更喜欢 `head` 那个模型的乱发和神态，考虑改用代码生成头发。

1. **减面和压缩**。把高面数模型减到网页能加载的规模，贴图压到 2K，输出到开发分支（例如 `assets/`）。
   目标：头 3–5 万面，刀 1 万，废墟 10 万左右。原始文件留在 `upload-3d-models` 分支不动。
2. **换头**。把绑骨全身模型里属于头和头发的顶点切掉，把新头摆正、对齐到脖子，刚性挂在 `mixamorig:Head` 骨骼上，接缝处匹配肤色。
   - 新头导出时整体带着低头侧转的角度，这个角度和原片姿势接近。做法是先把头对齐到骨骼坐标（数据上摆正），再用 `Head`/`Neck` 骨骼的旋转把这个低头角度还原成默认姿势，这样最终画面保留原来的角度，动画里头也还能转动。
   - 首选 `anime girl head`（整体最像原片）。头发和头一体，飘动用顶点 shader 按"离头皮的距离"摆动发梢。
   - 如果发梢摆动效果不够，换成 `bald female head` + `hair wig`，头发是独立网格，更好做动态。
3. **角色转台**。纯色背景下只放角色，套上最终的光照和 shader（逆光勾边、皮肤透光、眼睛发光），从正面、侧面、原片机位截图确认。**这一步过关再往下做。**
4. **姿势和动画**。半蹲拔刀的关键帧动画；刀拆成刀身和刀鞘，分别挂到手和腰上。
5. **场景和后期**。废墟平台、天空、雾和体积光；HDR 管线加景深光斑、辉光、运动模糊、调色、胶片颗粒。
6. **特效和爆发**。程序化闪电、水花、粒子。爆发段：出鞘瞬间短暂慢动作、地面冲击波、电弧四散、碎石浮空、镜头震动、一道刀光劈开远处烟尘。
7. **镜头和交互**。时间轴默认复刻原片运镜，可一键切到自由环绕，带时间条和慢放。
8. **对照迭代**。每改一轮用无头浏览器截图，和原片抽帧并排比较。

## 6. 已知风险

- **脸的近景**。原片靠刘海遮眼、逆光和浅景深藏住了脸，复刻时这些手段照用；贴脸正面特写仍是最弱的地方。
- **换头接缝**。两个模型的肤色和脖子粗细不一致，衣领能遮住一部分，剩下的要调色。
- **绑骨模型的蒙皮质量没验证过**。只看过 T 字姿势，蹲姿下肩、胯、裙子的变形要到第 4 步才知道。
- **体积**。原始素材约 480 MB，减面后预计几十 MB，早期"1.4 MB 纯代码"的设想已经放弃。
- **许可**。仓库是公开的，模型文件等于公开分发。Tripo 生成物的使用条款由用户自己确认。

## 7. 工具

脚本在 `tools/`，需要 Node 和 Playwright（云端环境已预装 Chromium 和 Playwright）。

```bash
cd tools && npm install          # 只装 three

# 取出某个模型（原始模型不在开发分支上）
git fetch origin upload-3d-models
git show "origin/upload-3d-models:anime girl head 3d model.glb" > /tmp/head.glb

node info.js /tmp/head.glb       # 面数、骨骼、贴图、包围盒
node view.js /tmp/head.glb out.png          # 四视图：正、侧、背、斜俯
node view.js /tmp/body.glb out.png 0.8 1.0  # 只看高度 80%–100% 的部分（头部特写）
node shot.js out.png             # 给 face/index.html 截图
```

没有 GPU 的环境用 SwiftShader 软件渲染，200 万面的模型也能出图，只是慢一些。
